# AI Knowledge Transfer (KT) Guide

This guide is designed for any AI or developer interacting with the Krayin CRM codebase. It explains the mental models required to understand and extend the system.

## 1. System Mental Model

Think of Krayin as a highly modular, event-driven, EAV-backed application built on top of Laravel.
- **Do not look for logic exclusively in Controllers**. Controllers are thin. They validate data via `FormRequests` and pass the array to a `Repository`.
- **Do not look for all database columns in Migrations**. Because of the EAV (Attribute) system, fields like "Job Title" or "Expected Revenue" might exist dynamically in the `attributes` and `lead_attribute_values` tables rather than as hard columns in the `leads` table.
- **Do not tightly couple modules**. If Lead needs to do something when an Activity is created, do not edit `ActivityController`. Listen to the `activity.create.after` event in a Service Provider.

## 2. Important Concepts

### The Repository Pattern
Every package has a `Repositories/` folder. If you need to create a Lead programmatically, you should inject the `LeadRepository` and call its `create(array $data)` method. This ensures that EAV attributes, events, and other standard processes are handled. Bypassing the repository and using `Lead::create()` directly will cause massive data inconsistency.

### Bouncer (ACL)
Permissions are strict. If you add a new route, you MUST define it in the relevant package's `Config/acl.php` and assign the `bouncer` middleware in `routes.php`.

### DataGrids
List views are generated by PHP classes extending `Webkul\DataGrid\DataGrid`. If you need to add a column to a table view, you must locate the specific DataGrid class (e.g., `LeadDataGrid.php`), add a column in the `prepareColumns()` method, and optionally modify the query in `prepareQueryBuilder()`.

## 3. Module Relationships
- **Leads** are the center of the CRM.
- **Activities** attach to Leads.
- **Attributes** govern the forms for Leads.

## 4. Common Questions

**Q: Where are the database migrations for custom fields?**
A: They don't exist. Custom fields are managed in the UI via Settings -> Attributes, which populates the `attributes` table.

**Q: I added a field to the database, but it's not showing up on the Create Lead form. Why?**
A: The Create Lead form loops over records in the `attributes` table. If you want a field to appear, you must create an Attribute via the UI (or a seeder), not just a database column.

**Q: How do I change what happens after an order/lead is saved?**
A: Locate the `EventServiceProvider` in the relevant package or create a new listener. Listen for `{entity}.create.after` or `{entity}.update.after`.

## 5. Code Navigation Guide

When investigating issues, follow this path:
- **UI/Vue Issues**: Look in `packages/Webkul/Admin/src/Resources/assets/js/components`.
- **Blade/Layout Issues**: Look in `packages/Webkul/Admin/src/Resources/views`.
- **Table/List View Issues**: Look in the `DataGrids` folder of the respective package.
- **Saving/Validation Issues**: Look in `Http/Requests` for validation rules, and `Repositories` for saving logic.
- **Permission Issues**: Check `Config/acl.php` and the `roles` database table.
